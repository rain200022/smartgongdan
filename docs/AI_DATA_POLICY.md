# AI 出站数据策略

## 适用范围

本策略约束 `openai_compatible` Provider 发往外部模型的工单分析与处理建议请求。默认的 `local` Provider 在本机运行，不产生模型出站请求。

## 强制数据最小化

外部请求只能包含完成当前分析或建议所需的字段。发送前必须基于副本递归脱敏，不能修改本地工单、知识、分析或审计记录。

当前自动替换：

- 邮箱地址：`[EMAIL]`
- 中国大陆手机号：`[PHONE]`
- IPv4 地址：`[IP_ADDRESS]`
- MAC 地址：`[MAC_ADDRESS]`
- 18 位身份证号：`[ID_NUMBER]`
- Windows 用户目录中的用户名：`[USER]`
- 显式标注的 password、token、secret、API key、密码、口令、令牌和密钥值：`[SENSITIVE]`
- Bearer 凭据：`Bearer [SENSITIVE]`

错误代码、端口、分类、设备类型和普通故障描述会保留，以维持诊断价值。脱敏规则位于 `app/services/redaction_service.py`，Provider 不得绕过该边界。

## 已知限制

自动规则不是完整匿名化。自然语言姓名、项目代号、客户名称、源代码、业务数据和未按常见格式书写的凭据仍可能出现在自由文本中。试点数据进入系统前仍需完成来源授权和人工脱敏；高敏工单不得提交给尚未通过供应商评审的外部模型。

## 供应商上线门槛

启用真实模型前必须书面确定：

- 请求数据不用于训练；
- 数据保留期限、删除机制和备份保留期；
- 数据存储与处理地域；
- 传输和静态加密；
- 供应商访问控制、审计和安全事件通知机制；
- 数据处理协议以及组织内部批准人。

未完成上述评审时保持 `AI_PROVIDER=local`。API Key 只能通过环境变量提供，不得写入仓库、日志或数据库。

## 验证证据

`tests/test_redaction.py` 固定常见敏感格式和诊断文本保留行为，`tests/test_ai_provider.py` 验证分析与解决建议的真实出站 JSON 均经过脱敏，并验证原对象没有被修改。
