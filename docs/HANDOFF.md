# 当前开发交接包

## 目标与验收

当前工作区实现 M5：在 M4 人工审核闭环基础上增加分类、检索、建议和处理时长四类指标，使用版本化检索基准集计算并留存 Recall@5，同时结构化记录建议拒绝原因。继续开发时必须保持现有 HTTP 路径、迁移历史、指标分母和审计记录的追加语义。

- 应用入口：`app.main:app`；应用工厂：`app.main:create_app`。
- 代码数据库版本：`20260907_0009`。本机 Docker 在 2026-09-07 因 `sailor-ingest.sock` 无法访问启动失败，本机数据库尚未应用本轮迁移；修复 Docker 后执行 `uv run alembic upgrade head` 和 `uv run alembic check`。

- `openai_compatible` 的分析与建议请求会在 Provider 边界生成脱敏副本；本地业务与审计数据保持原值。
- PostgreSQL/pgvector 由 `docker compose up -d db` 启动。
- 前端入口：`frontend/src/main.ts`；登录路径：`/login`；用户端路径：`/portal/tickets`；员工端路径：`/console/tickets`；管理员账号路径：`/console/users`。
- 前端统一使用 Ant Design Vue 和 `frontend/src/styles/tokens.css`，不混用组件库。
- 样本目录包含 15 篇知识与 30 条已解决工单；`scripts.seed_search_data` 可幂等导入。
- 分类试点评测通过版本化清单将 30 条人工标注基础样例确定性扩展为 120 条受控表达变体；它是格式鲁棒性压力测试，不是 120 条独立真实工单。
- 完整业务证据位于 `tests/`，本轮本地验证 112 项后端测试通过、覆盖率 96.89%，4 项 PostgreSQL 用例因数据库不可用跳过；`frontend/e2e/` 的 11 项 Chromium 流程回归通过，含移动端详情、认领隔离、版本冲突和保稿检查。CI 额外使用独立 PostgreSQL 测试库运行并发用例。
- 用户详情路径为 `/portal/tickets/{id}`，两端列表均使用服务端分页、搜索和筛选；员工列表展示后台返回的状态总数。
- 草稿只存于标签页内存，按账号／工单隔离；同账号会话恢复保留草稿，退出或切换账号清除。重新分析不会重置人工修改的最终处理内容。
- GitHub Actions 包含后端、前端质量检查和独立浏览器回归三个任务。测试服务使用临时 SQLite、固定测试账号与独立端口，生产应用没有测试接口。
- 工单认领与释放、负责人显示、追加式 `ticket_events` 审计已接通。所有员工写接口支持 `X-Ticket-Version`；前端强制发送，旧客户端可省略但不具备旧页面编辑保护。管理员可处理／释放他人认领工单，其他工程师只读；未认领时兼容原流程。
- 外部 AI/向量调用结束后才通过原子条件更新预占版本；并发失败不会写入部分判断、分析、建议或审计记录。建议因重新分析过期时，后端拒绝审核。

## 关键边界与不变量

- 依赖方向和编码规范见根目录 `AGENTS.md`。
- 项目行为契约见 `docs/PROJECT_CONTRACT.md`。
- AI 与工程师判断只能追加；关闭工单不可修改；分类必须来自分类树。
- AI 不得直接决定 P1–P4；`priority_service` 按 50/30/20 权重计算并保留分项证据。
- 相似检索仅向员工开放，结果来自关键词与 pgvector 两路候选的确定性融合。
- AI 建议只能引用本次 Top 5 证据；虚构引用会导致整次生成失败且不写入部分记录。
- 建议按次追加保存；审核另存且一条建议只能审核一次。采纳只填充草稿，不自动执行或关闭。
- 采纳率只以已审核建议为分母；处理时长必须排除带 `external_reference` 的导入历史案例。
- Recall@5 基准数据带固定版本；每次运行追加 `search_evaluation_runs`，不得覆盖旧结果。
- 已关闭工单不可为了补向量而修改；样本导入遇到已有历史引用时必须跳过。
- 普通用户只能访问 `requester_id` 属于自己的工单；工程师与管理员权限由后端依赖强制执行。
- 会话原始令牌不得写入数据库、日志、localStorage 或文档。
- 外部模型请求必须经过 `redaction_service`；不得直接序列化数据库对象或加入关闭脱敏的配置开关。
- 停用账号和管理员重置密码会撤销目标账号的全部会话；当前管理员不能对自己执行这两个动作。
- 不得在未经明确需求时加入公开注册、自动执行建议、自动关闭或自动派单。
