# Smart Gongdan 项目契约

## 目的与当前范围

当前版本是 M5 单体工单系统。它支持账号登录、三角色权限、管理员账号生命周期管理、工单归属、工单 CRUD 闭环、AI 结构化理解、规则优先级、知识与历史案例混合检索、有证据引用的 AI 处理建议、受控分类、审核留痕，以及分类、检索、采纳和处理时长评估。

当前明确不包含公开注册、多租户、企业 SSO、自动执行建议、自动关闭和自动派单。这些能力不得被隐式加入。

## 入口与依赖方向

运行入口是 `app.main:app`，数据库迁移入口是 Alembic，开发数据库由 `docker-compose.yml` 提供。

```text
HTTP -> app/api -> app/services -> app/models + app/db
                    |             -> app/core
                    -> AIService provider boundary
```

API 层不持有业务规则；服务层不依赖 FastAPI；模型层不依赖服务或 API。

## 稳定行为与数据契约

- 现有 HTTP 路径保持兼容。
- 匿名请求只能访问健康检查、API 文档和登录接口。
- 普通用户只能查看 `requester_id` 等于自身 ID 的工单；员工角色可以查看全局队列。
- 工单详情与列表共用后端归属校验；用户详情展示自己的问题、当前状态和最终方案。
- 工单列表使用服务端筛选和分页；`status_counts` 统计权限、搜索、优先级范围内的各状态总数，`total` 额外应用当前状态筛选。
- 工单优先级筛选以人工 `final_priority` 为先，没有人工值时使用 `ai_priority`；搜索中的通配符按字面匹配。
- 更新、AI 分析、分类确认和关闭工单仅允许 `ENGINEER` 或 `ADMIN`。
- 用户管理接口仅允许 `ADMIN`；公开自助注册保持关闭。
- 会话令牌仅通过 HttpOnly Cookie 传输，数据库只持久化令牌摘要。
- 停用账号或由管理员重置密码时必须在同一事务内撤销该账号的全部会话。
- 当前管理员不能通过管理接口停用自己或重置自己的密码。
- 前端草稿仅在标签页内存中按账号／工单保存；同一账号过期重新登录可恢复，主动退出或换账号清除。不得把凭证或工单正文持久化到浏览器存储。
- 工程师重新分析时保留已手工修改的处理字段；前端写操作互斥、丢弃切换工单后的迟到结果。此机制不替代后续后端并发冲突保护。
- 过期会话统一引导重新登录；禁止自动重放写请求。
- 分类必须来自 `CLASSIFICATION_TREE`，无法判断时使用 `其他/未分类`。
- AI 分析、AI 判断和工程师判断均追加保存，不覆盖历史。
- AI 只能提取影响、紧急度和影响范围；P1–P4 必须由 `priority_service` 的确定性规则计算。
- 每次新分析保存其优先级事实、分项分数、总分和规则结果，并更新工单最新 `ai_priority`；历史分析不回填推测值。
- 相似结果只允许员工角色访问；普通用户不得读取知识库或其他用户的历史工单。
- AI 处理建议的生成、读取和审核只允许员工角色访问。
- 外部 AI Provider 只能接收数据最小化后的副本；常见直接标识符和显式凭据必须在 Provider 边界脱敏，本地持久化数据不得被改写。
- 生产检索使用 PostgreSQL 关键词查询和 pgvector 精确余弦近邻，并通过确定性融合规则去重排序。
- AI 建议输入必须包含最新分析、用户已尝试操作和最多五条检索证据；引用必须属于该证据集。
- AI 建议按次追加保存，不覆盖历史；Provider 失败或引用越界不得写入部分建议。
- 与用户已尝试操作重复的建议步骤由业务服务过滤；过滤后无步骤必须标记人工接管。
- 建议审核单独保存且每条建议只能审核一次；采纳或拒绝不得自动执行、改变状态或关闭工单。
- 建议采纳率的分母是已审核建议，待审核建议不得进入分母。
- 拒绝原因类型来自固定枚举，旧客户端未提供类型时按 `OTHER` 保存以保持兼容。
- 处理时长只统计没有 `external_reference` 的真实关闭工单，导入历史案例不得进入指标。
- Recall@5 使用版本化基准集逐条计算期望引用的召回比例后取宏平均；每次评估追加保存，不覆盖历史运行。
- 分类鲁棒性试点由 30 条人工标注基础样例和版本化变体清单确定性生成；合成变体不得被表述为独立真实工单或真实准确率证据。
- 关闭工单时，检索向量与关闭状态在同一事务提交；嵌入失败不得产生部分关闭结果。
- 样本历史工单导入保持幂等，已存在的关闭工单不得被覆盖。
- 导入的历史工单只用于检索，不得混入工程师日常工单队列。
- 人工确认与当时最新 AI 判断生成不可变评估记录。
- 全局一致率按每张工单最新人工确认统计；没有 AI 结果的人工确认不进入分母。
- 关闭后的工单不可编辑。
- 生产表结构只能通过 Alembic 迁移变化。

上述行为由 `tests/test_auth.py`、`tests/test_tickets.py`、`tests/test_ai_analysis.py`、`tests/test_priority_service.py`、`tests/test_search.py`、`tests/test_solutions.py`、`tests/test_mvp_metrics.py`、`tests/test_classification_evaluation.py` 和 `tests/test_pilot_evaluation.py` 固定。

## 非功能约束

- Python 3.11+；UTC 时区；UTF-8 源文件；100 字符行宽。
- API Provider 超时由 `AI_TIMEOUT_SECONDS` 控制。
- 外部模型返回必须经过 Pydantic 和受控分类树验证。
- 外部模型出站字段和脱敏范围见 `docs/AI_DATA_POLICY.md`；不得提供关闭脱敏的运行时开关。
- 密码使用 pwdlib 推荐的 Argon2 哈希；原始密码和会话令牌不得记录。
- 质量门禁为 Ruff、Mypy、Pytest 覆盖率 90% 以上、前端 ESLint/TypeScript/构建及 Alembic 模型漂移检查。
- 浏览器回归独立验证账号登录、提交、处理关闭、用户结果查看、分页、草稿恢复与账号隔离；使用 `scripts.e2e_server` 创建临时 SQLite 测试服务，生产入口仍只使用 Alembic 管理结构。

## 已知风险与未决事项

- 当前账号模型适用于单组织 MVP；生产暴露前仍需启用 HTTPS、Secure Cookie、登录限流、自助改密/找回和账号操作审计策略。
- 多人同时处理仍需后端版本冲突保护、认领与操作人审计；当前浏览器测试使用 SQLite，PostgreSQL/pgvector 专有查询仍需增加集成测试。
- 本地规则分析器仅用于开发基线，不代表真实模型效果。
- 120 条分类鲁棒性样例源自 30 条基础样例的受控变体，不能替代经授权和独立标注的真实工单评测集。
- 本地哈希嵌入器仅用于离线开发和检索链路验证，不代表生产语义召回效果。
- 一致率查询目前适合 MVP 数据规模；数据量增长后应改为数据库窗口查询或聚合视图。
- HTTP 测试当前使用 Starlette `TestClient`，依赖栈会产生一条上游弃用警告，后续升级时应迁移到推荐客户端。
- 自动脱敏无法可靠识别自然语言姓名、项目代号和业务机密；生产启用真实模型前仍需完成供应商数据保留评审与试点数据人工治理。

## 证据与回滚

可复现检查命令记录在根目录 `AGENTS.md`。代码变更可通过 Git 回滚；数据库变更使用相应 Alembic 迁移的 `downgrade()`，执行生产降级前必须人工备份和审核。
